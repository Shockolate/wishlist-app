# Wishlist App: Plan Roadmap

**Spec:** [`docs/superpowers/specs/2026-10-07-wishlist-app-design.md`](../specs/2026-10-07-wishlist-app-design.md)

The spec is delivered as five sequential plans. **Each plan is written only after the previous one has merged**, so it builds on the code that actually exists and on the spike results, not on guesses. This applies in particular to three findings from Plan 1:

- the merge method for stacked PRs,
- which header carries the real client IP through the Next.js rewrite,
- how preview aliases work.

Every plan ends with software that is deployed and tested on its own.
